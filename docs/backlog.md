## Priorización y dependencias

El scaffold Spring/health (UL-02), PostgreSQL/migración (UL-03) y deploy temprano
(UL-20a) forman una ruta independiente del CRUD completo. El deploy depende solo
del scaffold y PostgreSQL, por lo que el objetivo del 9 de octubre ya no espera
endpoints/login/CI acabados.

UL-10 (DSW-16) comprueba solo arranque y conectividad local. UL-16 (DSW-22) es
la verificación funcional de API con Postman. Las pruebas automatizadas de
repositorios y seguridad siguen siendo responsabilidad de quien implementa esos
módulos.

UL-08 (DSW-13) implementa CRUD básico. UL-17 (DSW-28) implementa reglas
backend de etapas y seguimientos; UL-18 (DSW-21) es la API de dashboard y UL-19
(DSW-23) es su UI. UL-14 (DSW-19) es la API de bitácora; UL-15b (DSW-27)
integra sus datos en el detalle. La UI consume contratos existentes y no añade
endpoints. El build (DSW-25) y deploy temprano (DSW-26), junto con DSW-14,
DSW-27 y DSW-23, deben estar listos antes de la release integrada DSW-24.

Linear reserva Urgent para el login académico (DSW-9) y el CRUD REST evaluado
(DSW-13). High marca trabajo crítico; Medium, diseño, Postman de autenticación,
CI y smoke test de arranque. Los bloqueos nativos están en Linear: el deploy
temprano requiere solo scaffold y DB, el dashboard no espera notas, y la
primera ronda de QA requiere las pantallas, reglas y release integradas. Las
correcciones y re-pruebas ocurren después de esa ronda.
